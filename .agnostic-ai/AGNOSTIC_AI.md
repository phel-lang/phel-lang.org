# phel-lang.org

The website of the Phel language (https://phel-lang.org): a Zola static site with the documentation, the API reference, the practice exercises, the blog and the release notes. The language itself lives in the phel-lang/phel-lang repository.

## Where things live

| Path | What |
|---|---|
| `content/documentation/` | Docs: `language/`, `guides/`, `web/`, `libraries/`, `tooling/`, `reference/`, and the three start pages at the root |
| `content/practice/` | The practice journey, 11 modules from first steps to projects |
| `content/blog/`, `content/releases/` | Blog posts; release notes generated from GitHub releases |
| `templates/`, `templates/components/` | Tera 2 templates and the components content calls |
| `css/`, `static/` | Styles (built into `static/tailwind.css`), scripts, images |
| `build/` | PHP generators (API, errors, releases), the doc-snippet runner, their tests |
| `scripts/` | Node helpers: CSS concat, llms-full, doc dates, internal link check |

Repository policy is in the rules below, for Claude Code and Codex alike. Keep it in `.agnostic-ai/`: `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.codex/` and `.agents/` are generated by `agnostic-ai sync` and gitignored, and a hook blocks hand edits to them and to the site's generated pages. Paths in rules and skills are relative to the repository root.

After pulling spec changes, run `agnostic-ai sync` so both tools see them.
